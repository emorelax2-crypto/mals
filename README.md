# Mals Chat

ИИ-ассистент для чата: один «оператор» держит десятки переписок круглосуточно.
Ставится виджетом на сайт одной строкой или подключается к приложению по API.

Работает на **Claude Opus 5**.

---

## Что умеет

| | |
|---|---|
| **Много диалогов разом** | Очередь держит до 50 параллельных ответов (число настраивается). Внутри одного диалога реплики не перемешиваются. |
| **24/7** | Отвечает ночью, в выходные и в наплыв заявок. |
| **Ключевые слова** | Клиент пишет «цена» — ассистент получает ваши факты и прикладывает к ответу фото и карточку товара. |
| **Свои фото** | Загружаются в панели, привязываются к правилам мышкой. |
| **Перехват диалога** | Один клик — ИИ замолкает, дальше пишете вы. Клиент видит пометку «живой человек». |
| **Виджет и API** | Сайт, мобильное приложение, Telegram-бот — один ассистент и общая история переписки. |
| **Инбокс** | Все переписки в одном списке, живое обновление, поиск, счётчики непрочитанного. |
| **Песочница** | Проверить ответ, не трогая реальные диалоги. |

## Быстрый старт

```bash
npm install
cp .env.example .env     # впишите ANTHROPIC_API_KEY и ADMIN_PASSWORD
npm start
```

Откройте:

* `http://localhost:3000` — демо-страница с работающим виджетом;
* `http://localhost:3000/admin` — панель управления (пароль из `ADMIN_PASSWORD`).

Ключ Anthropic берётся на <https://console.anthropic.com/settings/keys>.

### Настройки (`.env`)

| Переменная | Зачем | По умолчанию |
|---|---|---|
| `ANTHROPIC_API_KEY` | Ключ API — обязателен | — |
| `ADMIN_PASSWORD` | Пароль в админку — обязателен | — |
| `PORT` | Порт сервера | `3000` |
| `PUBLIC_URL` | Публичный адрес: подставляется в код виджета и ссылки на фото | `http://localhost:3000` |
| `MAX_CONCURRENT_REPLIES` | Сколько ответов генерировать одновременно | `50` |
| `HISTORY_LIMIT` | Сколько последних сообщений отправлять в модель как контекст | `24` |
| `SESSION_SECRET` | Подпись сессий админки. Без него после перезапуска нужен повторный вход | генерируется |
| `DATA_DIR` | Где лежит база sqlite | `./data` |

## Подключение

### Виджет на сайт

Одна строка перед `</body>` — на любом движке, включая Тильду и WordPress:

```html
<script src="https://ваш-домен/widget.js" async></script>
```

Цвет, заголовок и угол экрана меняются в панели, без правки кода.

### Своё приложение или бот

Создайте API-ключ в панели → «Подключение», дальше один POST-запрос:

```bash
curl -X POST https://ваш-домен/api/v1/chat \
  -H "X-API-Key: mals_ваш_ключ" \
  -H "Content-Type: application/json" \
  -d '{"channel":"telegram","contact_id":"user-42","contact_name":"Иван","text":"Сколько стоит доставка?"}'
```

Ответ:

```json
{
  "conversation_id": "1f0c…",
  "reply": "Доставка по России 390 ₽, а от 5000 ₽ — бесплатно. Куда везём?",
  "attachments": [
    { "type": "image", "url": "https://ваш-домен/uploads/1737…png" },
    { "type": "card", "name": "Runner Pro", "price": "4 900 ₽", "url": "https://…", "buttonText": "Купить" }
  ],
  "status": "ok"
}
```

История подтягивается сама по паре `channel` + `contact_id` — хранить контекст на своей стороне не нужно.

| Метод | Что делает |
|---|---|
| `POST /api/v1/chat` | Сообщение клиента → ответ ассистента и вложения |
| `POST /api/v1/messages` | Записать реплику в диалог без ответа ИИ |
| `GET /api/v1/conversations/:channel/:contact_id` | История переписки |

Если диалог перехвачен живым менеджером, ответ приходит со `status: "handled_by_operator"` и `reply: null` — ваше приложение просто ничего не отправляет клиенту.

## Как это устроено

```
Клиент ──WebSocket/REST──▶ сервер ──▶ очередь (до 50 разом) ──▶ Claude Opus 5
                             │                                      │
                      ключевые слова ──────справка + фото───────────┘
                             │
                        sqlite (диалоги, правила, медиа)
                             │
                       панель управления (живой инбокс)
```

* `src/server.js` — HTTP и WebSocket.
* `src/chat.js` — приём сообщения, постановка ответа в очередь, перехват оператором.
* `src/queue.js` — два ограничителя: общий предел параллельных запросов и замок на диалог.
* `src/ai.js` — запрос к модели, системный промпт, обработка ошибок API.
* `src/triggers.js` — сопоставление ключевых слов, справка для модели, вложения.
* `src/db.js` — схема sqlite и запросы.
* `public/widget.js` — встраиваемый виджет (свой изолированный CSS, чтобы не ломать чужую вёрстку).
* `public/admin/` — панель управления.

### Оформление берётся готовым

Шрифты — Google Fonts, разметка — Tailwind, реактивность — Alpine.js, иконки — Lucide.
Всё грузится с CDN. Если CDN недоступен (корпоративная сеть, блокировка, оффлайн-демо),
страница подхватывает те же версии из `public/vendor` — копии кладёт `npm install`.

## Ассистент не притворяется человеком

Персона настраивается как угодно — имя, характер, тон, что продаёте. Но поверх вашего
текста на сервере всегда добавляется блок правил, который из панели не отключается:

* на прямой вопрос «ты бот?» ассистент отвечает честно;
* не выдаёт себя за конкретного живого человека и не обещает прийти на встречу;
* не переводит разговор в романтический формат;
* не выдумывает цены, сроки и наличие — если данных нет, зовёт живого менеджера;
* не давит дедлайнами и не обещает того, что компания не подтверждала.

Полный текст правил виден в панели на вкладке «Ассистент». Он лежит в `src/ai.js`
в константе `GROUND_RULES`.

Это не формальность: чат, который выдаёт бота за живого человека, ломает доверие
клиентов и попадает под блокировки площадок и закон о защите прав потребителей.

## Что стоит сделать перед продакшеном

* Поставить за nginx или Caddy с HTTPS — виджет на чужом сайте требует `wss://`.
* Задать `SESSION_SECRET`, иначе вход слетает при каждом перезапуске.
* Настроить бэкап `data/mals.db` и папки `public/uploads`.
* Ограничить частоту запросов к `/api/v1/*` на уровне прокси.
* Следить за расходом токенов: счётчик за сутки виден в `usage_log`.
